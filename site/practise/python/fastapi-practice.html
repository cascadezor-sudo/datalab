Собери API сервиса регистрации

От простого GET-маршрута — к проверке JSON, работе с PostgreSQL и валидируемому ответу.

Python · FastAPI · PydanticУровень: базовыйФормат: локальный проект
Что собрать

Одно приложение app.py с маршрутами для приветствия, суммы, даты и регистрации пользователя. Затем подключить чтение пользователя и поста из PostgreSQL.

1. Создай папку проекта и виртуальное окружение 
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install "fastapi[standard]"

Создай файл app.py. После первого этапа запускай сервер из папки проекта:

uvicorn app:app --reload --port 8000

Интерактивная проверка API: http://127.0.0.1:8000/docs.

Иди по этапам по порядку. Проверяй каждый маршрут в Swagger UI (/docs) и смотри не только на тело ответа, но и на HTTP-статус.

1Первый маршрут

Создай экземпляр приложения с именем app и маршрут GET /, который возвращает строку "hello, world".

  • Запусти сервер и открой корневой адрес.
  • Проверь маршрут также через /docs.
  • Зафиксируй, какой статус вернулся и как FastAPI представил строку в ответе.
Подсказка
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return "hello, world"

2Query-параметры и типы

Добавь GET /sum с обязательными целочисленными параметрами a и b. Он должен возвращать их сумму.

  • /sum?a=5&b=3 возвращает 8.
  • Проверь запрос без параметра и запрос с текстом вместо числа. Посмотри код и детали ошибки.
Подсказка
@app.get("/sum")
def sum_numbers(a: int, b: int) -> int:
    return a + b

3Дата и валидация параметров

Добавь GET /sum_date с параметрами current_date в формате YYYY-MM-DD и целым offset. Верни дату, сдвинутую на указанное число дней.

  • Проверь ?current_date=2008-09-15&offset=2 → 2008-09-17.
  • Проверь отрицательный сдвиг, невалидную дату и нецелое смещение. Некорректные параметры должны получить ошибку валидации.
Подсказка
from datetime import date, timedelta

@app.get("/sum_date")
def sum_date(current_date: date, offset: int) -> str:
    return (current_date + timedelta(days=offset)).isoformat()

4POST-запрос и Pydantic-модель

Опиши модель User с обязательными полями name: str, surname: str, age: int, registration_date: date. Создай POST /user/validate, который принимает JSON-модель и отвечает строкой Will add user: <имя> <фамилия> with age <возраст>.

Проверь валидный JSON, JSON без обязательных полей, неверный тип age и неверную дату. Для ошибочных тел ожидай статус 422.

Подсказка
from datetime import date
from pydantic import BaseModel

class User(BaseModel):
    name: str
    surname: str
    age: int
    registration_date: date

@app.post("/user/validate")
def validate_user(user: User) -> str:
    return f"Will add user: {user.name} {user.surname} with age {user.age}"

5Чтение из PostgreSQL

Расширь API маршрутом GET /user/{id}: он ищет пользователя по ID и возвращает JSON с полями gender, age и city.

  1. Добавь подключение psycopg2 и настрой его через переменную окружения DATABASE_URL.
  2. Параметризуй SQL-запрос: значение ID передавай отдельно, а не склеивай строку запроса.
  3. Если записи нет, верни 404 и JSON {"detail":"user not found"}.
Подключение к БД
Используй собственную строку подключения, выданную для твоей базы. Не записывай логин и пароль в app.py и не добавляй их в Git.
Подсказка по переменной окружения в PowerShell
$env:DATABASE_URL = "postgresql://USER:PASSWORD@HOST:PORT/DBNAME"
py -m pip install psycopg2-binary
Подсказка по обработке отсутствующего пользователя
from fastapi import HTTPException

if user is None:
    raise HTTPException(status_code=404, detail="user not found")

6Внедрение зависимости

Вынеси создание подключения в функцию get_db(). Передай подключение обработчику через Depends, а закрытие соединения размести в finally или используй зависимость с yield.

После переноса проверь запрос к GET /user/{id} и убедись, что подключение освобождается даже при ошибке.

Подсказка: форма зависимости с yield
import os
from typing import Iterator
from fastapi import Depends
import psycopg2


def get_db() -> Iterator:
    connection = psycopg2.connect(os.environ["DATABASE_URL"])
    try:
        yield connection
    finally:
        connection.close()

@app.get("/user/{user_id}")
def get_user(user_id: int, db = Depends(get_db)):
    ...

7Контракт ответа

Добавь GET /post/{id}. Опиши PostResponse с полями id: int, text: str и topic: str, укажи модель в response_model и верни найденную запись как данные модели.

  • Для отсутствующего поста верни 404 до построения ответа.
  • Проверь, что лишние поля из строки БД не попадают наружу, а некорректные значения ответа выявляются валидацией.
  • Сверь фактическую JSON-структуру с описанием модели.
Подсказка
class PostResponse(BaseModel):
    id: int
    text: str
    topic: str

@app.get("/post/{post_id}", response_model=PostResponse)
def get_post(post_id: int, db = Depends(get_db)):

Итоговая проверка

  • Приложение запускается командой uvicorn app:app --reload --port 8000.
  • Все маршруты видны в /docs.
  • Неверные входные данные дают понятный 422, отсутствующие записи — 404.
  • Доступ к БД передаётся через зависимость и закрывается после запроса.
  • Ответы ограничены указанными Pydantic-моделями.
  • Секреты и персональные данные не попали в исходный код или Git.
