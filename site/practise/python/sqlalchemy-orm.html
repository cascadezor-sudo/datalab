Собери API поверх ORM-моделей

Преобразуй таблицы user, post и feed_action в ORM-модели, напиши выборки, добавь связи и выдай результаты через FastAPI.

Python · SQLAlchemy 2.x · FastAPIУровень: базовыйФормат: API-проект
Задача

Сделай маленький сервис чтения ленты. Основной маршрут отдаёт популярные посты, дополнительные — пользователя, пост и действия по ним.

Материал модуля показывает SQLAlchemy 1.4 и старый стиль запросов. Здесь задания сохранены, а примеры приведены к декларативному mapping и select() из SQLAlchemy 2.x.

python -m venv .venv
# активируй окружение, затем:
pip install "sqlalchemy>=2,<3" fastapi uvicorn pydantic

Для первой итерации используй SQLite. Для PostgreSQL подключи собственный URL через переменную окружения.

1. Опиши таблицы моделями

Создай Base и модели User, Post, FeedAction. В учебной схеме нужны поля пользователя (страна, город, возраст, группа, ОС), публикации (текст, тема) и действий (тип и время).

from datetime import datetime
from sqlalchemy import ForeignKey, String, DateTime
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship

class Base(DeclarativeBase):
    pass

class Post(Base):
    __tablename__ = "post"
    id: Mapped[int] = mapped_column(primary_key=True)
    text: Mapped[str] = mapped_column(String)
    topic: Mapped[str] = mapped_column(String(80), index=True)

class FeedAction(Base):
    __tablename__ = "feed_action"
    id: Mapped[int] = mapped_column(primary_key=True)
    user_id: Mapped[int] = mapped_column(ForeignKey("user.id"), index=True)
    post_id: Mapped[int] = mapped_column(ForeignKey("post.id"), index=True)
    action: Mapped[str] = mapped_column(String(16))
    time: Mapped[datetime] = mapped_column(DateTime(timezone=True))
    post: Mapped[Post] = relationship()

Добавь User со связями и внешними ключами. Убедись, что ключи отражают реальные связи, а типы колонок подходят для данных.

2. Перенеси задания в ORM-запросы

  • Выбери последние 10 постов темы business, упорядочив по убыванию id.
  • Найди число пользователей по стране и ОС среди группы 3; оставь группы больше 100 и отсортируй по убыванию размера.
  • Выбери действия для заданного пользователя или поста в порядке от новых к старым.
  • Реализуй топ постов по числу лайков. Лимит маршрута должен быть ограничен разумным диапазоном.
from sqlalchemy import select

stmt = (
    select(Post)
    .where(Post.topic == "business")
    .order_by(Post.id.desc())
    .limit(10)
)
posts = session.scalars(stmt).all()

Для группировки выбирай только поля группировки и агрегаты; для нескольких таблиц явно задавай условия соединения.

3. Добавь FastAPI-маршруты и схемы ответа

  • GET /user/{user_id} и GET /post/{post_id} возвращают запись или HTTP 404.
  • GET /user/{user_id}/feed?limit=10 отдаёт последние действия; если записей нет, верни пустой список.
  • GET /post/recommendations/?limit=10 отдаёт посты, отсортированные по числу лайков.
  • Сессия базы создаётся на запрос и закрывается после него; не держи глобальную открытую Session.

Создай Pydantic-схемы ответа отдельно от ORM-моделей. Вложенный ответ может включать автора и пост. Не сериализуй секретные поля пользователя.

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine("sqlite:///./practice.db")
SessionLocal = sessionmaker(engine)

def get_session():
    with SessionLocal() as session:
        yield session

В каждом обработчике получай session через Depends(get_session), а результат валидируй схемой ответа.

4. Проверь изменение схемы через Alembic

После первой версии добавь поле или индекс и создай миграцию. Посмотри, какие DDL-команды Alembic сгенерировал, и проверь upgrade/downgrade на тестовой базе.

Не запускай create_all() как замену миграциям в развиваемом приложении: он не версионирует изменения существующей схемы.

Критерии готовности

  • Модели создают корректные таблицы и внешние ключи в локальной базе.
  • Выборки возвращают ожидаемые строки и порядок; пустые результаты и неверные id обработаны.
  • API отдаёт JSON по схемам, а сессии корректно закрываются.
  • Топ лайков устойчив к равным значениям; миграция воспроизводится на чистой базе.
Подсказка для топа лайков

Сгруппируй действия по post_id, отфильтруй action = 'like', соедини агрегат с Post, отсортируй по count по убыванию и добавь вторичный порядок по id для стабильного результата.
