Построй DAG для ежедневного отчёта

Разбей обработку активности на задачи, передай небольшой результат между шагами и научись безопасно повторять запуск за выбранную дату.

Apache Airflow · PythonУровень: базовыйФормат: DAG и упражнения
Цель

Описать workflow из трёх этапов: определить дату обработки, посчитать метрики активности, сохранить короткую сводку. Airflow управляет порядком и повторными запусками, а бизнес-логику держим в обычных Python-функциях.

DAG — ориентированный ациклический граф задач. Он описывает расписание, зависимости, повторы и параметры запуска. Задачи выполняют отдельные действия, а не весь pipeline одной длинной функцией.

В приложенных уроках используются старые импорты и schedule_interval. Ниже показан интерфейс Airflow 3.x; для старого окружения потребуется адаптировать импорты по версии Airflow.

1. Создай DAG с зависимостями

Создай файл в папке DAGs. Укажи ежедневное расписание, дату начала и catchup=False. Начни с двух задач — проверки параметра и подготовки сводки.

from datetime import datetime
from airflow.sdk import dag, task

@dag(
    dag_id="daily_activity_summary",
    schedule="@daily",
    start_date=datetime(2025, 1, 1),
    catchup=False,
    tags=["practice"],
)
def daily_activity_summary():
    @task
    def get_processing_date() -> str:
        from airflow.sdk import get_current_context
        context = get_current_context()
        return context["ds"]

    @task
    def build_summary(processing_date: str) -> dict:
        # Позже замени заглушку запросом к учебной базе
        return {"date": processing_date, "views": 0, "likes": 0}

    build_summary(get_processing_date())

daily_activity_summary()

Проверь DAG в интерфейсе и локальной CLI-команде доступной версии. Убедись, что задачи распознаны и порядок зависимостей соответствует замыслу.

2. Передай небольшой результат между задачами

TaskFlow передаёт возвращаемое значение следующей задаче через XCom. Это подходит для даты, счётчика, идентификатора или пути к файлу.

  • Добавь шаг проверки, что дата имеет ожидаемый формат.
  • Добавь шаг отчёта, который получает словарь метрик и пишет короткую строку в лог.
  • Сохраняй большой CSV/таблицу во внешнем хранилище, а через XCom передавай только путь или ключ объекта.

Повтори задания из исходного урока с операторами: выведи дату через BashOperator, передай аргумент в PythonOperator и сравни ручной XCom с автоматической передачей TaskFlow.

3. Добавь ветвление и подключение к базе

  • Вынеси выбор SQL-подключения в Airflow Connection; не записывай пароль в файл DAG.
  • Используй provider hook для чтения из PostgreSQL и параметризованный SQL-запрос.
  • Добавь ветку: если за дату нет строк, пропусти публикацию отчёта и заверши DAG корректным статусом.
  • Передай порог или флаг через Params/Variables, если это конфигурация запуска, а не секрет.

Отдельно проверь поведение при отсутствии данных и при временной ошибке базы. Повтор должен быть безопасным и не создавать дубликаты.

Критерии готовности

  • Зависимости видны в графе и выполняются в нужном порядке.
  • Дата берётся из контекста Airflow, а не из datetime.now().
  • Повторный запуск за тот же интервал даёт тот же результат.
  • XCom содержит только компактные значения; пароли хранятся в Connections.
  • Функции обработки данных можно протестировать без запуска scheduler.
Что ещё потренировать по исходным заданиям

Сгенерируй цикл из нескольких независимых задач, добавь документацию DAG в Markdown, выведи run_id и ts в лог и реализуй условную ветку. Сравни динамическое создание задач с динамическим task mapping: выбирай второй подход, когда список входов становится известен во время выполнения.
