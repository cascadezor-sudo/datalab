От Python-запроса к Redash-дашборду

Подключись к PostgreSQL из Python, исследуй ленту действий и собери в Redash отчёт по просмотрам и лайкам. Практика опирается на задания модуля, а не повторяет базовый SQL.

Python · PostgreSQL · pandasУровень: базовый SQLФормат: проект и дашборд
Что получится

Небольшой отчёт по пользовательской активности: ты выполнишь несколько запросов из Python, сохранишь агрегаты и соберёшь в Redash таблицу и график.

В учебной схеме используются три таблицы: user (пользователь, страна, город, группа, ОС), post (текст и тема публикации) и feed_action (пользователь, публикация, действие, время). Для работы с реальной базой понадобятся собственные разрешённые реквизиты подключения.

1. Подключись к PostgreSQL из Python

Создай виртуальное окружение и установи psycopg2-binary и pandas. Строку подключения держи в переменной окружения DATABASE_URL, не в ноутбуке.

import os
import pandas as pd
from sqlalchemy import create_engine

engine = create_engine(os.environ["DATABASE_URL"])
query = """
SELECT topic, COUNT(*) AS actions
FROM post
GROUP BY topic
ORDER BY actions DESC
"""
with engine.connect() as connection:
    topics = pd.read_sql_query(query, connection)

topics.head()

Если используешь psycopg2 напрямую, закрывай курсор и соединение через контекстные менеджеры. Для повторяющихся запросов с параметрами передавай параметры отдельно, не склеивай SQL f-строками.

Нужен доступ к учебной или собственной PostgreSQL-базе. Страница намеренно не содержит адресов, логинов и паролей из материалов курса.

2. Выполни исследовательские запросы

Профиль аудитории

Посчитай пользователей по стране и экспериментальной группе; сравни средний возраст по ОС.

Контент

Найди темы с наибольшим числом публикаций и самую длинную публикацию в каждой теме.

Активность

Сгруппируй просмотры и лайки по дате и теме публикации; проверь, что join не умножил строки.

Сегмент

Сравни активность пользователей из Москвы по группам и выдели сегмент с возрастом выше среднего.

Проверь агрегат до визуализации

  • Сначала сформулируй гранулярность результата: одна строка на день и тему.
  • Отдельно посчитай просмотры и лайки, чтобы не смешивать метрики.
  • Проверь результат на небольшом диапазоне дат и вручную сверь несколько строк.

3. Собери отчёт в Redash

  1. Открой доступный тебе источник данных, создай новый запрос и выполни агрегирующий SQL.
  2. Сохрани запрос с понятным названием, например «Активность по темам и дням».
  3. Создай визуализацию: линия для динамики просмотров или таблица для сравнения тем.
  4. Создай дашборд, добавь сохранённую визуализацию и подпиши, что означает метрика.
  5. Проверь диапазон дат и обнови данные перед публикацией дашборда.

Redash здесь выступает интерфейсом для запуска SQL, визуализации результата и размещения виджетов на дашборде. Для действий в Redash используй выданный тебе аккаунт и доступные источники.

Когда проект готов

  • Код подключается к базе через переменную окружения, реквизиты не попали в notebook или git.
  • Запросы возвращают ожидаемую гранулярность, joins и агрегаты проверены.
  • В Redash есть сохранённый запрос, визуализация с подписями осей и дашборд.
  • В выводах есть 2–3 наблюдения о разнице активности по темам или сегментам.
Подсказка: что проверить, если числа выглядят слишком большими

Посчитай строки до и после join. Если у публикации несколько действий, а соединение выполнено с обеими таблицами «многие-ко-многим», агрегат может размножиться. Сведи каждую сторону до нужной гранулярности до объединения.
