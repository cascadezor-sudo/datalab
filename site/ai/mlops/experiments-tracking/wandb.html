Weights & Biases

Материалы по W&B и трекингу экспериментов.

    Блок 1

  1. Что такое Weights & Biases?↗

    Weights & Biases (W&B, wandb) — платформа для experiment tracking, визуализации, артефактов, отчётов и командной работы над ML-экспериментами. Чаще всего используется как SaaS, но есть и варианты self-hosted для организаций.

    W&B делает сильный акцент на удобном UI и collaboration: runs автоматически группируются в projects, графики строятся без ручной настройки, отчёты можно собирать прямо в интерфейсе, а артефакты связываются в lineage.

    W&B удобен, когда экспериментов много и их нужно обсуждать в команде:

    • быстро сравнивать runs и sweep-ы
    • смотреть системные метрики GPU/CPU
    • хранить графики, таблицы, изображения и модели
    • делать reports для ревью экспериментов
    • отслеживать lineage датасетов и моделей через artifacts
    • запускать hyperparameter sweeps

    Перед использованием SaaS-версии нужно понять, какие данные можно отправлять наружу. Метрики обычно безопасны, но изображения, тексты, датасеты, предсказания и артефакты модели могут содержать коммерческую тайну или персональные данные.

    1. Что такое W&B run?

      Один запуск эксперимента с config, metrics, logs, media, artifacts и metadata.

    2. Сильная сторона W&B по сравнению с простым TensorBoard?

      Командный UI, reports, artifacts, sweeps, удобное сравнение runs и collaboration.

    3. Какой главный риск SaaS-трекинга?

      Случайная отправка чувствительных данных или артефактов во внешний сервис.

  2. Логирование runs в wandb↗

    В W&B запуск начинается с wandb.init(). В config кладут гиперпараметры и настройки эксперимента, а через wandb.log() отправляют метрики по шагам.

    import wandb run = wandb.init( project="churn-classification", config={ "model": "random_forest", "n_estimators": 300, "max_depth": 8, "dataset_version": "2026-05-01", }, ) for epoch in range(num_epochs): train_loss = train_one_epoch() valid_f1 = evaluate() wandb.log({"train/loss": train_loss, "valid/f1": valid_f1, "epoch": epoch}) run.finish()

    config должен описывать не только гиперпараметры модели, но и контекст: версия данных, split, seed, preprocessing, feature set, commit, режим обучения. Тогда run можно честно сравнить с другими и воспроизвести.

    Слишком частое логирование создаёт шум, замедляет обучение и делает UI трудночитаемым. Для batch-level loss можно логировать каждые N шагов, а для validation-метрик — раз в эпоху или evaluation step.

    1. Что обычно кладут в wandb.config?

      Гиперпараметры, версию данных, preprocessing, seed, feature set, commit и другие настройки запуска.

    2. Для чего используется wandb.log()?

      Для записи метрик, изображений, таблиц и других значений по шагам эксперимента.

    3. Почему важно не логировать слишком часто?

      Это создаёт overhead, увеличивает объём данных и усложняет анализ графиков.

  3. W&B Artifacts и lineage↗

    W&B Artifacts — механизм версионирования файлов и связей между ними: датасетов, моделей, predictions, таблиц, отчётов и любых файлов, которые важны для эксперимента.

    Artifacts позволяют построить lineage: какой датасет использовался для обучения, какой run создал модель, какая модель дала predictions и какой отчёт их анализировал.

    import wandb run = wandb.init(project="churn-classification") artifact = wandb.Artifact("churn-model", type="model") artifact.add_file("model.pkl") artifact.metadata = {"valid_f1": 0.842, "dataset_version": "2026-05-01"} run.log_artifact(artifact) run.finish()
    ТипЧто хранить
    datasetВерсионированные данные или ссылки на них
    modelВеса, pickle, checkpoint, ONNX
    predictionsТаблицы предсказаний для анализа ошибок
    evaluationОтчёты, confusion matrix, calibration plots

    Если датасет большой или чувствительный, в artifact можно хранить manifest, hash, URI в private storage и metadata. Не обязательно загружать исходные данные в W&B.

    1. Что такое artifact в W&B?

      Версионируемый объект с файлами и metadata, связанный с run.

    2. Что такое lineage?

      Граф происхождения: какие данные, runs, модели и результаты связаны между собой.

    3. Как безопасно работать с чувствительными датасетами?

      Хранить ссылку, hash и metadata, а сами данные оставлять в защищённом storage.

  4. Sweeps и Reports в W&B↗

    W&B Sweeps — инструмент для автоматического перебора гиперпараметров. Reports — интерактивные документы, в которых команда фиксирует выводы по runs, графикам, таблицам и артефактам.

    Sweep задаёт пространство параметров, стратегию поиска и целевую метрику. Agent запускает training script с разными config, а W&B собирает результаты в один project.

    program: train.py method: bayes metric: name: valid/f1 goal: maximize parameters: learning_rate: min: 0.0001 max: 0.01 batch_size: values: [32, 64, 128] dropout: values: [0.1, 0.2, 0.4]

    Хороший report отвечает не «какой run лучший», а почему он лучший: какие гиперпараметры влияли на метрику, какие ошибки остались, какие эксперименты отклонены и что нужно проверить дальше.

    Автоматический перебор не спасёт, если метрика выбрана неверно, validation split протекает, данные загрязнены или диапазоны параметров заданы без понимания модели.

    1. Что задаёт sweep-конфигурация?

      Training program, метод поиска, целевую метрику и пространство гиперпараметров.

    2. Зачем нужны W&B Reports?

      Чтобы фиксировать выводы по экспериментам и делать результаты понятными для команды.

    3. Почему sweep может дать ложный результат?

      Если validation set, метрика, данные или диапазоны гиперпараметров выбраны неправильно.
