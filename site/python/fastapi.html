FastAPI: от HTTP-запроса до API

Разбираем маршруты, параметры, проверку данных через Pydantic, ответы и зависимости. В конце — план небольшого API, который можно запустить локально.

  1. Что такое API и как FastAPI обрабатывает запрос?

    API описывает, как одна программа обращается к другой: по какому адресу и HTTP-методу, какие данные отправляет и какой ответ получит.

    Например, браузер отправляет GET /tasks/42. Сервер ищет задачу с номером 42 и возвращает JSON вместе с HTTP-статусом. API задаёт форму и смысл запроса и ответа.

    Клиент ── GET /tasks/42 ──▶ FastAPI
Клиент ◀─ 200 + JSON ───── FastAPI

    Маршрут связывает HTTP-метод и путь с Python-функцией. В FastAPI такую функцию называют обработчиком операции пути.

    • GET читает данные;
    • POST обычно создаёт ресурс;
    • PUT заменяет ресурс целиком, PATCH меняет часть;
    • DELETE удаляет ресурс.

    URL обычно называет ресурс — например, /tasks, — а не действие вроде /getTasks. Один и тот же путь может иметь разные обработчики для GET и POST.

    FastAPI разбирает HTTP-запрос, передаёт значения аргументам функции и упаковывает результат в HTTP-ответ. Starlette отвечает за веб-слой, а Pydantic используется для схем и валидации данных.

    HTTP-запрос содержит метод, путь, заголовки и иногда тело. Ответ содержит статус, заголовки и обычно тело. API — это согласованный контракт между клиентом и сервером.

  2. Как запустить первое приложение?

    Объект FastAPI хранит маршруты и настройки приложения. Декоратор @app.get("/health") регистрирует функцию, которая будет вызвана для запроса GET /health.

    Создай виртуальное окружение, установи FastAPI со стандартными инструментами и сохрани пример в main.py:

    python -m venv .venv
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
python -m pip install "fastapi[standard]"
    from fastapi import FastAPI

app = FastAPI(title="Tasks API")


@app.get("/health")
def health_check():
    return {"status": "ok"}


@app.get("/")
def read_root():
    return {"message": "Мой первый API"}

    Из папки с файлом запусти fastapi dev main.py. Сервер для разработки будет доступен по адресу http://127.0.0.1:8000.

    Открой /docs, чтобы проверить запрос через Swagger UI, или /redoc, чтобы посмотреть документацию в ReDoc. Схема OpenAPI доступна по /openapi.json. FastAPI строит её из маршрутов, аннотаций типов и моделей.

  3. Как принять и проверить входные данные?
    • Path-параметр находится в пути: /tasks/{task_id}. Аннотация int просит преобразовать значение в число и проверить его.
    • Query-параметр идёт после ?: /tasks?done=true. Простой аргумент функции, которого нет в пути, читается из query-строки.
    • Тело запроса обычно содержит JSON. Модель Pydantic описывает его поля, типы, обязательность и ограничения.
    from pydantic import BaseModel, Field


class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=120)
    done: bool = False


@app.get("/tasks/{task_id}")
def read_task(task_id: int, verbose: bool = False):
    return {"id": task_id, "verbose": verbose}


@app.post("/tasks")
def create_task(task: TaskCreate):
    return {"title": task.title, "done": task.done}

    В GET /tasks/7?verbose=true число 7 берётся из пути, а true — из query. В POST /tasks поля задачи приходят в JSON-теле.

    Если передать строку вместо целого числа или нарушить ограничение min_length, FastAPI вернёт структурированную ошибку валидации со статусом 422 и не вызовет обработчик с невалидными данными. Это сокращает ручные проверки, но не заменяет бизнес-правила: например, уникальность названия задачи надо проверять отдельно.

    Для явного описания источника есть Path(), Query() и Body(). Больше о моделях — в расширенном Python.

  4. Как описать ответ и вернуть ошибку?

    Статус сообщает клиенту результат операции: 200 OK — успешно, 201 Created — ресурс создан, 204 No Content — успешно, но без тела, 404 Not Found — ресурс не найден. Статус — часть контракта, его нельзя рассматривать как техническую мелочь.

    from fastapi import HTTPException, status
from pydantic import BaseModel


class TaskPublic(BaseModel):
    id: int
    title: str
    done: bool


@app.post(
    "/tasks",
    response_model=TaskPublic,
    status_code=status.HTTP_201_CREATED,
)
def create_task(task: TaskCreate):
    return {"id": 1, "title": task.title, "done": task.done}


@app.get("/tasks/{task_id}", response_model=TaskPublic)
def read_task(task_id: int):
    task = find_task(task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Задача не найдена")
    return task

    response_model описывает публичную форму ответа, участвует в документации и не даёт случайно выдать клиенту лишние поля. HTTPException прекращает выполнение обработчика и возвращает HTTP-ошибку с заданным статусом и пояснением.

    422 означает, что входные данные не прошли проверку. 404 означает, что ресурс не найден. Для создания ресурса укажи 201. Не возвращай текст ошибки со статусом 200: клиенту станет труднее правильно обработать ответ.

  5. Зачем нужны Depends, APIRouter и async?

    Depends позволяет объявить компонент, который FastAPI подготовит и передаст обработчику. Через зависимости обычно подключают общую проверку доступа, настройки приложения или сессию базы данных.

    from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()


def get_page_size() -> int:
    return 20


PageSize = Annotated[int, Depends(get_page_size)]


@app.get("/tasks")
def list_tasks(limit: PageSize):
    return {"limit": limit, "items": []}

    В настоящем приложении зависимость базы данных должна корректно закрывать сессию и учитывать транзакции. Сам факт использования Depends этого за тебя не гарантирует.

    В одном файле удобно показать идею. Затем маршруты группируют через APIRouter, а правила предметной области выносят в сервисные функции. Так обработчик HTTP не превращается в место, где одновременно живут маршрутизация, бизнес-логика и запросы к базе.

    И def, и async def подходят для обработчиков. Выбирай async def, когда внутри вызываешь асинхронные операции через await. Синхронный драйвер БД или time.sleep() внутри асинхронной функции всё равно блокируют выполнение. Подробности есть в разделе про async.

  6. Практика: собери API для списка задач

    Создай main.py, запусти fastapi dev main.py и проверяй запросы в /docs. Храни задачи в обычном словаре: на этом шаге важны HTTP и контракт API, а не база данных.

    1. Добавь GET /health с ответом {"status": "ok"}.
    2. Добавь GET /sum?a=3&b=4; ответ должен содержать сумму 7.
    3. Опиши входную модель задачи с непустым title и необязательным полем done.
    4. Сделай POST /tasks: добавляй новую задачу и возвращай код 201.
    5. Сделай GET /tasks/{task_id}: для неизвестного ID возвращай 404.
    • В /docs видны маршруты и схемы запроса/ответа.
    • Некорректный тип или пустой заголовок отклоняется проверкой.
    • Создание возвращает 201, неизвестная задача — 404.
    • После перезапуска данные пропадают — это ожидаемое ограничение словаря.
