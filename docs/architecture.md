# Архитектура DataLab

## Границы каталогов

```text
datalab/
├── Start_DataLab.bat       # основной запуск на Windows
├── start.bat               # короткая команда запуска
├── package.json            # команды Node.js без внешних зависимостей
├── README.md
├── README.txt
├── server/                 # HTTP-серверы и Python runner
├── site/                   # файлы, доступные браузеру
├── tools/
│   ├── generators/
│   │   ├── analytics/      # генераторы HTML и общий helper
│   │   └── flashcards/     # сборка карточек и манифеста блоков
│   ├── audits/             # чтение и проверка материалов
│   └── maintenance/        # разовые изменения исходников
├── tests/
│   ├── storage/            # localStorage, миграции, ссылки
│   ├── server/             # HTTP, выдача файлов, проверка упражнений
│   └── manual/             # старые диагностические HTML-снимки
└── docs/
```

`server/` раздаёт только каталог `site/`. Скрипты разработки, тесты и документация
находятся за пределами каталога сайта. Серверы вычисляют пути относительно своих
файлов; запуск из другой рабочей папки не меняет каталог сайта.

`tools/audits/` читает материалы. Генераторы и скрипты из `tools/maintenance/`
могут перезаписывать файлы: перед их запуском проверьте чистоту Git, после — diff.
Генераторы определяют корень проекта по своему расположению, а не по текущей папке.

Локальные резервные копии можно хранить в `.local/backups/`; каталог `.local/`
исключён из Git. Историю опубликованного кода хранит Git.

## Совместимость

Обычный запуск использует `http://localhost:8080/main.html`. Перемещение серверов
не меняет origin, URL страниц, идентификаторы вопросов или ключ `datalab_offline_db`.
Это сохраняет привязку браузерного прогресса к прежнему адресу.

Серверные тесты используют случайные свободные порты и отдельные процессы,
не занимая порт 8080. Они не обращаются к пользовательскому localStorage.

## Следующие этапы

Первый этап разделяет инструменты, серверы и сайт. Внутренняя структура `site/`
пока сохранена, чтобы перенос не затронул ссылки между 189 HTML-страницами.

Следующие самостоятельные изменения:

1. Убрать дубли JavaScript, обновив все подключения к ним.
2. Вынести учебные данные из JS в `assets/data/`, определить редактируемые
   источники и генерируемые результаты для каждого набора материалов.
3. Разделить хранилище, общие UI-компоненты и функции приложения на модули.
4. Упорядочить CSS и названия разделов; для старых URL предусмотреть совместимость.
