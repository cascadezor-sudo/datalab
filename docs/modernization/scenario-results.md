## Ширины и ошибки

`tests/browser/smoke.cjs`: шесть страниц (главная, Python Base, алгебра, повторение, roadmap, профиль), 320, 375, 390, 768 и 1440 px. Ответы 200, title непустой, необработанных `pageerror` за период открытия и ожидания 600 мс не наблюдалось. Проверка не охватывает console.error, поздние асинхронные сбои и все ресурсы. Открытие мобильного меню проверено на трёх ширинах ниже 768 px. Измерение `documentElement.scrollWidth` после загрузки: при 320 px roadmap — 322 px; остальные 29 сочетаний равны ширине viewport. Это не проверка доступности, клиппинга вложенных элементов или всех состояний.

Повторение в PowerShell с отдельной временной установкой Playwright и браузера:

```powershell
$qa = Join-Path $env:TEMP ('datalab-qa-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $qa | Out-Null
npm install --prefix $qa --no-save --no-package-lock playwright@1.65.1
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path $qa 'browsers'
& (Join-Path $qa 'node_modules/.bin/playwright.cmd') install chromium
$env:NODE_PATH = Join-Path $qa 'node_modules'
Remove-Item Env:DATALAB_CHROMIUM -ErrorAction SilentlyContinue
node tests/browser/smoke.cjs
node tests/browser/scenarios.cjs
```

В фактическом прогоне использован уже установленный Chromium revision 1254 через `DATALAB_CHROMIUM`; Playwright 1.65.1 по умолчанию ожидает свою версию браузера. Команда установки выше скачивает соответствующий браузер в новую временную папку и требует сеть.

Второй скрипт выводит результаты сценариев, включая ошибки и ограниченное ожидание Pyodide; это диагностический прогон, а не полный набор утверждений. Каждый сценарий использует отдельный свежий контекст.

`node --test` без NODE_PATH: 10/10 успешно; smoke не запускается автоматически и не добавляет зависимость проекта.

## Pages

`git archive HEAD site tools/build-pages.mjs` распакован Python tarfile в уникальную TEMP-папку и сборщик запущен там, а не в репозитории; его встроенная проверка префикса `/datalab/` прошла. Это HEAD-версия отслеживаемых файлов и **не включает** пользовательское незакоммиченное изменение `site/profile.html`; локальные браузерные проверки выше использовали рабочее дерево. В собранном HEAD-артефакте `.bak` файлов 0. Сборщик копирует физическое содержимое `site/`, поэтому прямой запуск из рабочего дерева может включить игнорируемые `.bak` файлы. Артефакт не публиковался. Проверка `python tools/audits/routes_inventory.py --site <TEMP>/stage/.local/pages --pages-artifact` вернула 189 страниц и 5 `missing_asset:pages` (exit 0): `ai/interviews/index.html` ссылается на отсутствующие `assets/icons/network.svg`, `compass.svg`, `play.svg`, `team.svg`, `dictionary.svg`; те же пять найдены в source audit. Первая распаковка Windows tar исказила кириллическое имя файла и дала ложное шестое замечание; повторная распаковка Python сохранила имя и устранила его. Реальные Pages в браузере и API Pages не проверялись.
