# Резервное копирование и восстановление: проект для Фазы 1

> Фаза 1.1: экспорт/импорт, вложенный предпросмотр, атомарный предимпортный снимок, guarded undo и восстановление после неудачной миграции реализованы. Пользовательская инструкция и ограничения — [storage-recovery.md](storage-recovery.md), результаты — [phase-1.1-report.md](phase-1.1-report.md). Остальной текст ниже сохраняется как первоначальная спецификация.

> Дополнение Фазы 1: одноразовый импорт использует маркер `datalab_anonymous_import_v1` и признак `datalab_migrations.anonymous_progress_v1` внутри базы. Их нужно учитывать вместе с `datalab_offline_db` и `anonymous_progress` при проектировании резервного копирования и отката. Восстановление только старой базы при сохранённом внешнем маркере может пропустить импорт. Готового пользовательского восстановления и безопасного отката между версиями пока нет; подробности — в [отчёте Фазы 1](phase-1-report.md).

Это спецификация, не реализованный экспорт/импорт. Существующее browser storage не открывалось. Проверки будущей реализации — только в изолированном origin/контексте на синтетических данных. До готовности механизма не менять модель хранения.

## Формат

Версионированный JSON-конверт `format: "datalab-local-backup"`, `version: 1`, `createdAt`, сведения об источнике (scheme, host, port и base path отдельно), версия приложения и список записей `{storage:"localStorage", key, raw}`. `raw` — точная строка localStorage, включая неизвестные поля, порядок, неподдающийся разбору JSON и пустые строки; отсутствующий ключ не равен пустому. Записи сортируются по ключу только для расчёта целостности. Include `datalab_offline_db`, все совместимые `*_offline_db`, `anonymous_progress`, `page_completion_*`, `exc-draft:*`, `math-answer:*`, `course-roadmap-demo-state`, диагностические данные и выявленные пользовательские настройки из storage-contracts. Вся DB сохраняется целиком, включая неизвестные ветви, quiz, SR, kanban, roadmap, достижения и настройки. Будущие ключи не предполагаются автоматически пользовательскими: новые шаблоны добавляются после аудита. Включение потенциально чувствительных ветвей внутри DB требует просмотра и явного выбора пользователем; auth/session/token/credentials и облачные секреты не экспортировать. Если секреты оказались внутри DB и их невозможно отделить без изменения raw, экспорт такой записи блокируется с объяснением и без ложного обещания полной копии; не делать скрытую фильтрацию. `sessionStorage` и производные staff/nav cache исключить по умолчанию.

Синтетический пример без персональных данных:

```json
{"format":"datalab-local-backup","version":1,"createdAt":"2026-01-01T00:00:00Z","source":{"origin":"http://localhost:8000","basePath":"/"},"entries":[{"storage":"localStorage","key":"anonymous_progress","raw":"{\"demo_question\":{\"completed\":true,\"unknown\":42}}"}],"integrity":{"algorithm":"SHA-256","canonicalization":"v1","digest":"<computed digest>"}}
```

Для реализации заранее специфицировать канонические UTF-8 байты и исключение самого digest из хеша; проверять длины, уникальность пары storage/key, допустимые ключи, ограничения размера, версию, схему и digest до любых записей. Хеш обнаруживает случайное повреждение, но не удостоверяет автора и не шифрует копию. Отдельно проверять наличие и декодирование DB без превращения некорректного raw в пустой объект. Не загружать файл в сеть; предупредить, что backup может содержать личные учебные данные.

## Восстановление

1. Определить целевой origin: localhost и Pages — разные пространства, даже если совпадают пути. Явно показать несовпадение source/target; base path не определяет origin. Перенос между origin — отдельное осознанное действие, не фоновая синхронизация.
2. При закрытых других вкладках приложения или гарантированной общей блокировке приостановить все writers и startup-мераджи. Существующий код не поддерживает такую блокировку: до её внедрения нельзя обещать атомарность. Сделать проверенную локальную предвосстановительную резервную копию целевого состояния и предложить сохранить её вне хранилища, включая отсутствующие ключи.
3. Проверить формат, версию, размер, hash, дубликаты и допустимые ключи; неизвестную версию отклонить без мутаций. Показать различия и конфликты. Дефолт — ничего не перезаписывать. Отсутствующие ключи можно добавить после явного выбора; различающиеся записи и идентичные ключи с разным raw требуют выбора на уровне ключа. Не объединять автоматически completion, черновики, результаты, удаления или anonymous с DB: порядок времени не всегда надёжен, а отсутствие записи может означать удаление. Исходные записи хранить раздельно; при желаемом merge сначала нужен проверенный доменный алгоритм и превью. Идентичные raw — no-op.
4. Оценить доступную квоту и пробную запись в изолированное временное пространство; расчёт приблизителен и не гарантирует успех. Применять только выбранный набор, подтверждать read-back каждого ключа, вести журнал прежних/новых значений и отсутствия. LocalStorage не даёт атомарной записи набора ключей; при квоте, закрытии вкладки или сбое возможен частичный импорт. При неудаче остановиться, попытаться восстановить затронутые ключи из журнала, проверить read-back и явно сообщить о любых ошибках; внешняя копия остаётся источником восстановления. Не запускать приложение до завершения/разрешения конфликта.
5. На успешном импорте проверить все выбранные raw, сохранить журнал/копии и затем разрешить writers. Повторное применение идентичного файла должно быть идемпотентно. Протестировать синтетически повреждённый JSON/hash, неоднозначные legacy ключи, отказ квоты, прерывание после каждого шага, одновременные вкладки, неизвестные поля, разные origin, отсутствие и пустую строку.

## Откат после новых записей

Немедленный откат возможен лишь если writers остановлены и текущие значения всё ещё совпадают с записанными импортом. После новых пользовательских изменений безусловное восстановление старого снимка уничтожило бы новые данные. Сначала экспортировать текущее состояние, сравнить `before / imported / current` по каждому ключу, показать конфликты и сохранить обе версии; перезапись только с явным выбором. Для безопасного автоматического отката нужен журнал доменных изменений/версий или поддержка транзакций, которых текущий код не предоставляет. Хранить копию вне localStorage на случай нехватки квоты и ошибок отката.
