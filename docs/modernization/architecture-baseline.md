## Структура и точки входа

| Часть | Назначение и вход |
| --- | --- |
| `site/` | Статические страницы, учебные материалы, медиа и браузерное приложение; обычный вход — `/main.html` |
| `site/assets/js/components/` | Навигация, поиск, учёт вопросов, тесты, практика, повторение и прочие UI-контроллеры |
| `site/assets/js/firebase-mock.js` | Локальная Firebase-подобная база и часть учебных API поверх localStorage |
| `site/assets/js/config/` и `site/assets/data/` | Категории, индексы вопросов, тесты, карточки, план, справочные данные и каталог достижений |
| `server/server.py` | Основной локальный HTTP-сервер и `POST /api/run` |
| `server/server.js` | Резервный локальный сервер; оба сервера используют `server/offline_runner.py` |
| `Start_DataLab.bat`, `start.bat` | Запуск на Windows; `npm start` запускает Node-сервер |
| `tools/generators/` | Генераторы материалов и карточек; они могут менять исходные файлы и не запускались при инвентаризации |
| `tools/audits/` | Проверки содержимого и внешних подключений |
| `tests/storage/`, `tests/server/` | Node-тесты модели localStorage и двух серверов |
| `.github/workflows/pages.yml` | CI: Node 22, Python 3.12, тесты, статическая сборка и публикация Pages |
| `tools/build-pages.mjs` | Копирует `site/` в `.local/pages/`, заменяет пути для `/datalab/` и добавляет версии CSS/JS |

`package.json` не объявляет npm-зависимостей. Локальные версии при проверке: Node `v24.17.0`, Python `3.14.7`, npm `11.13.0`; CI использует другие версии. Результаты `node --test` нужно читать вместе с областью покрытия, а не как проверку всего сайта.

## Зависимости и границы

- Большие учебные страницы содержат текст, таблицы, код, формулы и интерактивные блоки; локальные JS/CSS подключаются страницами и динамически. Реальные подключения на уровне HTML перечисляются в [манифесте маршрутов](routes-manifest.json); ссылки, формируемые JavaScript во время выполнения, требуют отдельной проверки.
- Навигация, поиск, фильтры и отметки связаны через глобальные объекты и DOM. Некоторые части определяют сущность по `.name[id]`, `data-md-id`, URL или номеру блока. Это контракты текущей реализации, даже если они неудобны.
- `questions-list.json`, категории, quiz registry, карточки и планы — разные источники с частично пересекающимися связями. Их нельзя считать полностью согласованными без сверки с HTML.
- Локальное состояние сохраняется в `datalab_offline_db` и дополнительных ключах. Подробная карта чтения/записи и ограничений — [storage-contracts.md](storage-contracts.md).
- Локальный `/api/run` и исполняемые в браузере примеры Pyodide — разные механизмы. На Pages локального сервера нет; Pyodide может потребовать сеть и поддержку Worker/WASM.
- В HTML найдены пять внешних подключений script/link: Feather Icons на двух страницах профиля и три подключения KaTeX на `site/tests/index.html`. `runnable-code-block.js` также может загружать Pyodide с CDN; проверка только HTML-тегов не покрывает динамические загрузки.
- В каталоге сайта 431 292 539 байт GIF; крупнейший `site/images/python/pyspy_flame.gif` занимает 31 147 078 байт. Это потенциальный вес ресурсов, а не измеренный LCP или INP.

## Сборка Pages и сохранность локальных файлов

`tools/build-pages.mjs` выполняет рекурсивное удаление `.local/pages` и затем копирует **весь физический** `site/`. Поэтому нельзя запускать его поверх пользовательской `.local/pages` без понимания её содержимого; в Фазе 0 сборка должна проверяться в изолированной временной копии.

Поскольку копируется весь каталог, локальный запуск скопирует и игнорируемые `.bak`, в отличие от обычного чистого Git checkout в Actions. Локальный артефакт следует проверять перед любым ручным распространением. Файлы не удалялись и не публиковались.

Static Pages не предоставляет `/api/run`. Хранилище разделяется по origin: `localhost`, `127.0.0.1`, иной порт и `cascadezor-sudo.github.io` имеют разные данные; один только путь `/datalab/` origin не меняет.

## Известные риски

1. Асинхронный evaluator достижений может сохранить устаревший снимок всей базы. Повторный импорт `anonymous_progress` может вернуть очищенные отметки. См. [контракты хранения](storage-contracts.md).
2. Две реализации `achievementApi` перезаписывают методы друг друга в зависимости от порядка загрузки.
3. Несовпадение заголовков клиента и серверов препятствует обычной локальной проверке Python; сценарий должен проверяться на реальном запросе клиента, а не только server fixture.
4. Часть блоковых тестов сопоставляет pathname без учёта префикса Pages; результаты независимой функциональной проверки и ограничения описаны в отчёте Фазы 0.
5. Существуют совпадающие question ID и несовпадающие authoring ID/якоря; один legacy ID нельзя автоматически считать несколькими независимыми результатами.
6. Локальные ответы, интервалы повторения, исторические unlocks и достижения не сводятся к одному boolean. Старый backup не содержит действия, совершённые после миграции.
7. `/api/run` выполняет доверенный код с правами текущего пользователя; временный каталог и таймаут не являются полноценной изоляцией.

## Решения, требующие отдельной проверки

- Переход на Astro, структура output и стратегия совместимости `.html`, `index.html`, якорей и `/datalab/`.
- Выбор React только после пилота состояния/жизненного цикла конкретного интерфейса; текущие контроллеры работают без React как технологии.
- Изменение формата хранилища и канонических идентификаторов — только после фиксации всех писателей и тестов обратной совместимости.
- Публикация full-text индекса, переход на другой origin, серверная синхронизация и выполнение кода в сети требуют самостоятельной оценки.
- Замена медиа и улучшение Core Web Vitals требуют измерений на репрезентативных страницах; текущие размеры файлов не являются замером производительности.

## Независимость DataLab и проверка секретов

Поиск по публичным текстовым исходникам, README, документации, серверу, инструментам и workflow по `shmidt`, `schmidt`, `шмидт` нашёл два упоминания в комментариях распространяемого JS: `site/assets/js/components/company-logos.js:84` (`schmidtml-lending`) и `site/assets/js/components/english-club.js:5` (`schmidtml-esc`). В доступном статическом поиске HTML/UI/README и доменов с этим написанием не найдено. Это проверка текстовых файлов, а не анализ истории Git или каждого бинарного изображения; комментарии в этой фазе не менялись.

Рекомендуется отдельно проверить происхождение обоих комментариев и заменить устаревшие внутренние названия нейтральным описанием без переименования ключей пользовательского хранилища. Результат не доказывает, что все сторонние учебные материалы принадлежат DataLab.

`.gitignore` исключает `.env`, `.env.*`, `.local/`, `node_modules/`, виртуальные окружения и `*.bak`. Проверка имён отслеживаемых файлов не обнаружила типичных имён приватных ключей; ограниченный поиск характерных форматов ключей по отслеживаемым текстовым файлам не вывел совпадений. Это не полноценное сканирование секретов и истории. Содержимое локальной базы и `LEARNING_PROGRESS.md` не экспортировалось; перед будущим commit нужно проверить список staged-файлов, а перед публикацией — полученный артефакт.
